# 术语表

本仓库用到的概念，按使用频率排序。每个条目都写成自包含的，可单独引用。

---

**图源（书源）**

一份描述「去哪里取数据、如何解析」的配置，通常是一个 `.txt` 或 `.json` 数据文件。
它本身不含任何漫画内容。阅读器读取这份配置后，按其中定义的规则去对应站点搜索、取目录、
取图片地址。同义词：书源、源、source。不同客户端的叫法不同，指向的是同一个东西。

**源站点**

图源配置指向的那个网站。图源的所有数据最终都来自这里。源站点改版、更换域名、停止服务，
都会让使用它的图源失效。

**搜索入口**

图源的第一个环节。定义去哪个站点、用什么地址与参数发起搜索请求。
这一环失效的表现为：该源下搜不到任何作品。

**结果解析**

图源的第二个环节。定义如何从搜索返回的页面或响应里提取书名、封面、
详情页链接。这一环失效的表现为：能搜到请求但结果列表为空、错乱或重复。

**目录接口**

图源的第三个环节。定义如何从详情页取得章节列表。
这一环失效的表现为：能搜到并看到详情页，但章节列表加载不出来。

**图片地址**

图源的第四个环节。定义如何从章节页取得每一页图片的真实 URL。
这一环失效的表现为：目录正常，但点开章节是白屏或转圈。

**三个硬指标**

判断一个图源能否使用的判据，须依次通过：**搜得到 → 目录出得来 → 图显示得出来**。
三项全过才算可用。只过前两项的源很常见，它们看起来正常但无法实际阅读。

**换源验证**

最快的故障定位方法：拿同一本作品，在搜索结果中的多个源下逐个点开。
只要有一个能正常阅读，就证明客户端、网络、账号均无问题，失效的只是个别源。
这一步能排除大部分误判，优先级高于重装、清缓存。

**防盗链（`Referer` 校验）**

图床（存图片的服务器）的一种访问控制策略：只允许来自特定页面的请求加载图片，
其他来源的请求返回 403 或空响应。漫画客户端的请求通常在 `Referer` 上不符合图床白名单，
因此图片加载失败，表现为白屏。**这是服务端策略，客户端侧无法绕过**，只能更换图源。

**图床**

实际存放漫画图片的服务器或服务。它可能与源站点是同一台服务器，也可能是独立的第三方服务
（对象存储、图床服务商）。前面「目录能出、图片白屏」的现象，就是目录走源站点、
图片走图床，而图床做了限制。

**整源失效**

四类失效之一。该源下所有作品都无法使用，通常因为源站点停服、更换域名或新增访问验证。

**单本失效**

四类失效之一。源本身正常，只有某一本作品打不开，原因是该作品在源站点被删除或下架。
这类情况不应导致删除整个图源。

**章节缺图**

四类失效之一。前面章节正常，中间部分章节无内容，属于源站点的数据缺失，客户端侧无法修复。

**图源保质期**

图源的可用时长。因为图源依赖源站点的页面结构，任何源最终都会失效，只是时间早晚。
这决定了两件事：不能只依赖单一来源；失效是常态，不是操作错误。
